# DSA Mastery Definition and Outcome Targets

Last updated: February 26, 2026  
Phase: Setup and DSA Learning System (Phase 0)

## Objective of This Note
Define what "DSA mastery" means in measurable terms so your daily practice is focused.

## Mastery Definition
You can consider yourself interview-ready for a topic when all points below are true:
- You identify the core pattern in 2 to 5 minutes.
- You produce a correct brute-force approach before optimization.
- You derive an optimized approach with clear tradeoffs.
- You implement without major syntax struggle.
- You explain complexity and edge cases confidently.
- You can re-solve the same problem after 7+ days without hints.

## Outcome Targets by Use Case
### Interview Target
- Solve easy in 10 to 15 minutes and medium in 25 to 40 minutes.
- Communicate approach clearly while coding.
- Finish with at least 3 edge-case tests.

### Competitive Programming Target
- Build speed on pattern recognition and implementation.
- Reduce wrong submissions from indexing, overflow, and corner-case misses.
- Maintain a reusable snippets/template repository.

### Engineering Target
- Translate DSA patterns into production constraints: memory, latency, readability.
- Choose data structures based on operation profile, not habit.
- Write maintainable code with clear invariants and tests.

## Weekly Metrics
Track these every week:
- Accuracy rate: correct solves / total attempts.
- First-attempt acceptance rate.
- Average solve time per difficulty.
- Hint dependency percentage.
- Re-solve success rate (D+7 and D+30).

## Baseline Test (Day 1)
1. Attempt 2 easy and 2 medium mixed-topic problems in 90 minutes.
2. Avoid external hints.
3. Record solve time, failure reasons, and missing concepts.

## Exit Criteria for Phase 0
- [ ] You have written mastery metrics in a tracker.
- [ ] You have completed one baseline timed session.
- [ ] You know your top 3 current weak patterns.
- [ ] You set a weekly review block for metric updates.
